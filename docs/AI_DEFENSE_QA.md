# AI 补充答辩题

教师原题见 [30 道 MySQL 答辩题](DEFENSE_QA.md)。AI 部分按下列十题复习。

## 1. 什么是 RAG？

**口述** 先检索相关知识，再把证据和问题交给模型生成答案。本系统在客服回答中展示真实片段和可核验引用。

**原理与实现** 用户问题与文档共用向量空间。检索 Top-K 后，模型只能从白名单片段引用，服务器检查 ID 和实际内容。代码在 `AiKnowledge.search` 与 `AiKnowledge.answer`。**追问** 没命中时会怎样？界面返回无法依据知识库回答。

## 2. 什么是 Embedding？

**口述** Embedding 是将文本映射为固定维度的数值向量，用来比较相近语义。

**原理与实现** 模型版本变化会改变向量空间。OrderFlow 为每篇文档记录模型、维度和空间哈希，通过 `AiProvider.embed` 保存归一化的双精度向量。**追问** 能否把不同维度或不同模型向量混用？当前配置只在相同命名空间检索。

## 3. 余弦相似度如何计算？

**口述** 向量点积除以各自范数的乘积，归一化之后直接做点积。

**原理与实现** 零向量被拒绝，检索按余弦降序。实现位于 `AiKnowledge.normalized` 与 `AiKnowledge.search`。**追问** 余弦为 1 是否证明文档答案完全正确？它度量方向，事实仍需核验。

## 4. 什么是 Top-K 检索？

**口述** 按相关度选出最高的 K 个候选。项目先用阈值过滤，再取前三。

**原理与实现** 少量文档上的精确向量比较简单可解释，分数低于 0.34 则不进入上下文。代码在 `AiKnowledge.search`。**追问** K 太大时有什么影响？会增加上下文和噪音。

## 5. 为什么不将百万订单全部向量化？

**口述** 订单销量、库存和支付金额是结构化统计，SQL 可以精确计算。客服检索的对象是公共规则文档。

**原理与实现** 全量向量化使写入、同步和授权成本上升，还未必能准确汇总金额。对照 `AiTools`、`AiInventory` 和 `backend/src/main/resources/ai/knowledge`。**追问** 实际需要搜索海量文本时怎么办？用近邻索引与元数据过滤。

## 6. Agent 和普通聊天机器人有什么区别？

**口述** Agent 在服务器限定的工具范围内选择并执行动作，再用真实结果回答。普通聊天可以只生成文本。

**原理与实现** `AiAgent.answer` 在一次请求中接收函数调用、执行只读 SQL 并将数据反馈。**追问** 它能自由执行多轮吗？三轮、六次工具的门槛由应用控制。

## 7. Tool Calling 如何工作？

**口述** 请求带工具名称与 JSON Schema，模型返回函数名、参数和调用 ID。应用执行后用相同 ID 把工具结果交回模型。

**原理与实现** `AiProvider.chat` 使用真实兼容协议，`AiAgent` 构造 `assistant.tool_calls` 和 `role=tool` 消息。**追问** Mock 如何证明？Mock 覆盖消息协议，工具选择质量必须用真实模型验收。

## 8. 如何防止 AI 执行危险 SQL？

**口述** 工具白名单、固定 SQL 模板、参数严格校验和只读数据库账号共同控制。

**原理与实现** `AiTools.run` 只把已验证的数值和日期绑定到占位符，`AiSql` 用只读连接拒绝写入。模型不能提供 SQL 语句或访问任意表。**追问** 系统提示是否能替代权限？权限在服务器端独立校验。

## 9. 如何降低模型幻觉？

**口述** 把统计与规则绑定到数据库和知识库，为答案提供可核实依据，证据不足时拒答。

**原理与实现** `AiKnowledge` 检查引用确在检索集合，`AiAgent` 检查回答数字是否出现于查询结果或参数，图表直接由 SQL 结果构造。**追问** 能否保证关联语义完全正确？真实提供商评测仍需人工核对。

## 10. 如何评估 AI 库存分析？

**口述** 用低库存、无流量、畅销低库存等样本比对数据库值与风险，再检查建议与数据是否一致。

**原理与实现** `AiInventory` 先算指标再允许模型选择候选行动。`tests/ai_acceptance.py` 对照库存余额和实付销量，并测试跨商家与坏建议。**追问** 可售天数无销量怎么处理？返回空值，按无销量单独解释。
