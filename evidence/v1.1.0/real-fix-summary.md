## 定位与修复

原数字校验用 BigDecimal 集合比较数字时，两侧的小数 scale 不一致，合法的 30 天窗口和状态表数字会被拒绝。金额校验把“元、万元”等展示格式与 SQL 原值精确比较。校验还从整个句子上下文识别百分比，使金额差额邻近的增长率被一起拒绝。已改为归一化数字、按单位和显示精度换算、按状态结果行核对，并用后端根据两条 SQL 结果计算的差额与变化率验证比例。比较日期工具参数会按问题窗口规范到最近完整 UTC 日。

还原后的原始回复说明第一次销售额回答本身正确，错误来自校验；订单状态与 Top 5 表格的行值同样正确。畅销与库存回复曾超出实际工具结果，趋势回复曾自行估算阶段均值。修复继续拒绝无法核对的内容，并向管理员显示 SQL 生成的系统摘要及原模型草稿。

系统在 5473 已重建后端，端点返回 HTTP 200，前后端 healthy。主从、Redis 容器 ID 未变，`order_items` 仍为 1,000,021 行，百炼配置和主密钥卷复用。
