# AI 配置中心验收

2026-11-27 北京时间，在 Apple Silicon 的独立候选版 Docker 项目实际升级、运行与测试。MySQL 和 Redis 沿用候选项目既有卷与端口。初始化日志确认主库执行 V120 迁移、原有 400,000 笔历史订单直接复用，且从库 GTID 追平后拥有一条配置记录。独立主密钥文件属主为 UID 10001，权限 0600。正式 V1.0、V1.0.1 和候选项目的 API 均通过连通检查。

| 项目 | 实际结果 |
|---|---|
| 首次配置和即时生效 | 管理员从无密钥状态开始，共用一个 Mock API Key 后跑通 Agent、RAG 和商家分析。未重启容器即可启用 |
| 测试与回滚 | 完成文本、回调随机挑战及工具回执、向量和知识库探测。仅返回 HTTP 200 文本的工具探针不通过。错误密钥拒绝保存，模拟 503 时基础商品业务仍可读 |
| 权限与密钥 | 顾客和商家无法管理配置，管理员写操作需要 CSRF。测试证实 GET 脱敏、数据库保存密文、随机 IV、跨字段替换与密文篡改被拒 |
| URL 边界 | 拒绝回环、私有网段、元数据地址、异常端口、用户信息及异常路径。运行连接器使用过滤后的 DNS 结果并关闭重定向 |
| 热切换与向量 | 切换 Chat 后续请求使用新模型且原向量可用。独立 Embedding 密钥与 11→12 维切换经过实际链路，重建十个向量后客服恢复 |
| 容器重建 | 重建后端后保留配置和独立密钥卷。通过接口清除 Embedding 密钥后保留聊天密钥、停用 AI，基础业务继续运行 |
| 原业务 | 三角色、订单、取消回补、并发扣库存、只读从库、Redis 命中与失效通过回归 |

连接测试和截图使用本地 Mock，销售等数据经真实 MySQL。首次脚本使用错了用量汇总的列名，修正后从已保存的 Chat 切换继续验证。三项模型的真实提供商调用及不同真实供应商组合待有授权凭据后执行。未准备正式标签或双仓库发布。本机运行使用从相同代码编译的前后端产物和 Compose 容器。Windows 实机未运行本轮验收。
